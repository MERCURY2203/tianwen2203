### 音乐 + 和 TA 一起听（已上线正式版）

- 用户需求：主屏幕加「音乐」App；导入 mp3 + 歌词（多格式）+ 封面、制作人等信息；唱片机小组件同步显示正在听的歌；播放页仿用户发的两张截图（封面取色背景、黑胶唱片、两个头像共用一副耳机、底部音符/聊天切换）；听歌时双方能说话，气泡从说话人头像下面冒出来。
- 用户确认：角色**会**在听歌途中主动说话；一起听时的对话**只进记忆**、不进聊天记录；聊天里也能**发邀请**；每次可以**选和谁一起听**。
- 做法：
  - 新表 `tracks`；歌曲文件存成 blob `music:audio:<id>`（**不进备份**，太大；导入备份时也不会删掉本机的歌曲文件），封面 `music:cover:<id>`。
  - 歌词 `web/src/music/lyrics.js`：LRC（多时间标签、offset、逐字时间、原文+翻译合并）、SRT、VTT、TXT；编码自动认 UTF-8 / GBK / Big5 / UTF-16。
  - mp3 自带信息 `web/src/music/id3.js`：ID3v2.2/2.3/2.4 的歌名、歌手、专辑、作词、作曲、编曲、制作人（TIPL）、封面、普通歌词（USLT）、滚动歌词（SYLT）。
  - 播放器 `web/src/music/player.js`：全局只有一个，换页不停；锁屏控件（Media Session）；列表/单曲/随机。
  - 一起听：每首歌开始时问一次 AI（`/music/plan`）要「开头一句 + 3～5 句跟着歌词时间说的话」，到点冒气泡；用户说一句 → `/music/say` 回一句。换歌 / 不一起听 / 关掉时记成事件 `music_session`（不在聊天界面显示），立刻交给记忆整理。只点开没说话、听不到 20 秒的不记。
  - 聊天邀请：输入框旁边耳机按钮 → 选歌 → 发出 `user_message`（`data.music`），显示成卡片，点「一起听」直接进播放页。
  - 桌面唱片机：音乐里有歌时显示那首歌的封面、歌手（一起听时加「和 TA 一起听」），点唱片播放/暂停，点文字进播放页。
- 新图标 `web/public/icons/music.png`（耳机，和其他图标同风格）。
- 第二轮（用户反馈）：气泡长句只显示一半 → 气泡改成头像下面左右两栏（左我、右 TA），放不下自动换行；唱片按剩余空间缩放（Safari 有工具栏时不再顶到头像）。新增「设置 → 音乐」：播放页背景三选一（跟封面颜色 / 固定颜色 / 自己的图片，图片可调暗色和模糊），以及「TA 跟着歌词主动说话」开关（关掉省一次 AI 费用）。存在 meta `musicLook`、blob `music:bg`。


### 顶部雾化：改成实心状态栏（已上线）

- 用户选 **s1**：`index.html` 改成 `default`（实心状态栏，页面从状态栏下面开始）。此时 iOS 报的高度是对的，`fitHeight()` 只在透明状态栏时才修正。
- **已经添加到主屏幕的用户要删掉图标重新添加**，新的状态栏才会生效。

### 全屏 / 白边问题（未解决）

**用户反馈**：iPhone 浏览器里软件不是全屏，顶部、底部有白边；安卓也要全屏，要求「自适应全屏」。后来补充：**添加到主屏幕之后也还有白边**；不要临时填充，要从源头解决；可以调整显示尺寸，其他不变，顶部底部颜色延长。

**截图里看到的情况**（iOS 26 Safari，底部是新版浮动工具栏）：
- 顶部时间/电量那一条是单独一块颜色，和页面有色差；
- 底部工具栏那一条也是单独一块颜色：朋友圈页面底部是白的，工具栏那条却是深紫色。

**依次试过的做法**（全部在 `splash-preview` 分支，都已发到预览网址）：

1. `9463a35` 按页面取色：每次换页，看页面最顶上、最底下实际是什么颜色（`main.jsx` 里的 `colorAt` / `syncEdges`），把最外层 `<html>` 的背景（上半截顶色、下半截底色的渐变）和 `theme-color` 都设成这个颜色；图片背景按图片边缘的平均色（只算不透明的部分，装饰线条那种透明 SVG 不算）。
   → 用户：**底部好了，顶部有色差**。原因推测：新版 Safari 顶栏取的是 `<html>` 的 `background-color`，而当时它被设成了底部颜色。
2. `af42eb9` `<html>` 底色改成顶部颜色，再在屏幕最顶、最底各放 1 像素的固定细条给 Safari 取色。
   → 用户：**顶部好了，底部又有色差**。说明顶栏、底栏都取的是同一个 `background-color`，1 像素细条没被当回事。
3. `51156ba` 底部改成在页面后面垫一块占半屏的固定色块（`z-index:-1`），只在浏览器栏那里露出来。
   → 用户发了上面两张截图，说「就是这种问题，不要临时填充，从源头解决」。
4. `a3a6a3b`「从根上改」：
   - `#root` 改成 `position: fixed` + `height: 100lvh`（铺到浏览器工具栏后面），开屏动画 `.splash` 同样；
   - 新增 `--bar-b = 100lvh - 100dvh`（工具栏占掉的高度），`--safe-b = env(safe-area-inset-bottom) + --bar-b`，所有底部有可点内容的地方本来就用 `--safe-b` 留空，所以内容自动让开工具栏；
   - 去掉之前垫的色块；
   - 渐变背景的页面写明顶边颜色：`.home` 加 `background-color: var(--night)`，朋友圈封面 `.wx-cover` 加 `background-color: #312e46`；取色时顶边优先用这个写明的颜色。
   → 用户：**不要白边**，让我给方案选。
5. 给了四个方案（A 引导添加到主屏幕 / B 顶部底部统一深色 / C 黑色边框 / D 改成可滚动网页结构）。
   → 用户：**添加到主屏幕也还是有白边**；可以调整显示尺寸，其他不变，就是顶部底部颜色延长。
6. `53c2482` 顶部/底部颜色延长：
   - 页面后面垫两块延长色块（`.edge-ext`，`z-index:-1`），上面一块用当前页面顶部颜色、下面一块用底部颜色，各往屏幕外再多伸 200px；
   - `<html>` 背景：底色 = 顶部颜色，上半截顶色、下半截底色；
   - **手机上去掉 `body` 的浅灰紫底色 `#d9d5df`**（它原本是给电脑上显示手机外框用的，在手机上页面边一露缝就是一条「白边」，很可能是主屏幕模式下白边的来源）；电脑上照旧。
   → 用户：**还是没成功**。

7. `50c0719` 用户发来主屏幕模式截图（顶部一截灰、底部一条浅灰紫，高度约等于状态栏）。找到两个源头：
   - **CSS 写错顺序**：手机上把 `body` 底色改透明的 `@media` 写在 `body { background:#d9d5df }` **前面**，被后面覆盖，从来没生效 → 改成默认透明，只在电脑尺寸加浅灰紫。截图里那条正是 `#d9d5df`。
   - **iPhone 主屏幕模式高度少一截**：iOS 在 standalone 下报给网页的高度少了状态栏那段，页面从最顶上画，底下就空出一条 → `main.jsx` 加 `fitHeight()`，只在 iPhone 主屏幕模式下把 `--app-h` 设成屏幕真实高度，`#root`/`.splash` 用 `height: var(--app-h, 100lvh)`。
   - 只发到预览网址。注意：主屏幕图标要**删掉后从预览网址重新添加**，否则打开的是正式版。
   → 等用户反馈。

**目前的判断 / 下一步可以查的方向**：
- 我这边没有 iPhone，只能用电脑模拟手机屏幕，模拟器里看不出 Safari 顶栏/底栏的取色，也看不出主屏幕模式的效果，全靠用户截图反馈。下一步最好让用户在 **Safari** 和 **主屏幕图标** 两种打开方式下各截一张最新版的图，并确认已刷新到新版本（预览网址可能被缓存：可以在网址后面加 `?v=数字` 强制刷新）。
- 主屏幕模式（standalone）下仍有白边，说明不只是 Safari 浏览器栏的事。可疑点：
  - 旧版本被缓存：主屏幕图标打开的可能还是旧代码（service worker `sw.js` 对页面是「先联网」，但 iOS 主屏幕应用缓存比较顽固，可能需要删掉图标重新添加）。另外主屏幕图标若是从正式网址添加的，打开的是**正式版**，不是预览版。
  - `index.html` 里 `apple-mobile-web-app-status-bar-style` 是 `black-translucent`（内容铺到状态栏下面），配合 `viewport-fit=cover` 理论上能全屏；需要确认实际高度：可以在页面上临时显示 `innerHeight`、`screen.height`、`100lvh`、`env(safe-area-inset-*)` 的数值，让用户截图，对照找出白边到底是哪一块、多高。
- 还可以考虑的做法：方案 B（所有页面顶部/底部统一一个固定颜色，取色永远对）；或把 `<html>`/`<body>` 设成 `min-height: calc(100% + env(safe-area-inset-top) + env(safe-area-inset-bottom))` 之类直接撑大。

**相关代码位置**：
- `web/src/main.jsx`：`colorAt`、`avgOfImage`、`syncEdges`、`edge()`（取色和延长色块），以及安卓 App 状态栏图标深浅 `setBarStyle`；
- `web/src/styles.css` 开头：`--safe-*`、`--bar-b`、`#root`、`.edge-ext`、手机上去掉 body 底色的 `@media`；
- `web/index.html`：viewport、theme-color、status-bar-style。

### 开屏动画接进本地版 / 预览网址（等用户确认）

- 视频版开屏（`b0132fe`）：`web/public/splash.mp4`（1MB，1080×1920，无声）；`web/src/splash.js` 负责播放。
  - 视频里钟摆摆到最右/最左/最右的时间点是 2.52 / 5.4 / 8.2 秒（用程序逐帧量摆杆角度算出来的）；

  - 7 秒后底部淡入「双击进入」（细黑体、白色、像呼吸一样明暗），双击任何时候都能进；退场是轻轻放大 + 淡出（视频没法像代码画的钟摆那样「停住再收走」）；

  - 视频 4 秒还没开始播就直接进入，播放出错也直接进入；
  - `server/static-local.mjs`、`server/app.mjs` 加上 `.mp4` 的文件类型。
- 用户第一次在电脑上「没看到动画」：原因是桌面 `小手机` 文件夹里有个**旧的「更新包.zip」**，启动时 `server/update.mjs` 自动把它解压，把新文件全换回了旧版（连名字都变回「小手机」），装完自动删掉了 zip，还多出一个没用的 `android` 文件夹。已把整个文件夹的程序文件重新同步一遍（`data/`、`.env`、`web/license.config.json` 没动，核对过 license 配置和原来一样）。**以后往桌面同步前，先确认文件夹里没有「更新包*.zip」。**

- 先按用户选的方案用代码画了一版（黄铜钟摆、竖排「迟叙机」/「欢迎」、底部「双击进入」、双击后钟摆停到中间再往上收走、只冷启动、设置开关、「嗒」声）`6b1ee09`，录了截图。

- 用户发来即梦生成的 10 秒视频（米白底），要求**背景改黑、字和刻度线改白**。处理方法（脚本在临时目录，思路记在这里方便以后重做）：
  - 黄铜钟摆按颜色饱和度抠出来保留原色；挂座和摆锤的高光颜色太浅会被当成背景挖掉，所以用几何方法补全：挂座中心固定在 (542,207)，摆长 901、摆锤半径 134（1080×1920 画面），每帧用摆杆的角度算出摆锤位置画圆补上，圆外只保留摆杆那一条和底下的小坠子；
  - 背景变纯黑；字：拿「去掉字和钟摆后的纸面」当参照，比纸面暗多少就有多白（字淡入淡出时也是干净的灰，不发脏）；
  - 钟摆在纸上的影子会变成白色光晕 → 钟摆周围一圈不变白；
  - 刻度线（中间竖线 + 底下弧线）单独从静止背景里提出来，加粗、提亮、加一点柔光，竖线中间的断口按整条线的横截面补齐，去掉小噪点；
  - 四周暗角、左上角的斜光、边缘噪点都压掉。
  - 成品：`桌面\开屏动画-黑底.mp4`；接进软件的是截到 8.35 秒、去掉声音、在 2.5 秒处加关键帧的版本。

## 发布流程备忘

1. 改代码 → `node --test server/test/*.test.mjs`（目前 58 个测试全过）。
2. 打包：`node web/build.mjs`（服务器版 dist）、`--local`（电脑纯前端版 dist-local）、`--pages`（公开网址 dist-pages）、`--app`（安卓，输出到 `source/android/...`，再复制到仓库根目录的 `app/src/main/assets/`）。
3. 推送 `main` → GitHub 自动打包 APK；把 `dist-pages` 复制到 `tianwen` 仓库根目录推送 → 公开网址更新（预览就复制到 `tianwen/preview/`）。
4. 同步桌面 `小手机` 文件夹：**先确认里面没有「更新包*.zip」**；不要动 `data/`、`.env`、`web/license.config.json`、APK 文件。
5. 源码仓库保持私有（里面有签名文件 keystore）；`tianwen` 公开仓库只放打包好的文件。
